## Аутентификация

Все запросы (кроме `/api/users/login` и статики) требуют заголовок
`x-user-id` (id залогиненного пользователя). Уровни доступа:

| Уровень | Требование | Используется в |
|---|---|---|
| `requireLogin` | `x-user-id` существующего активного пользователя | Чтение (GET) большинства ресурсов |
| `requireAuth` | + заголовок `x-edit-password`, верный пароль, роль не ниже `operator`, PIN не дефолтный | Запись (POST/PUT/DELETE) |
| `requireAdmin` | + роль `admin` | Управление пользователями, ликвидация организаций и т.п. |

Пустой PIN у пользователя автоматически понижает эффективную роль до
`viewer`, даже если в БД сохранена более высокая роль (см. `SEC-2` в
`server/middleware/auth.js`).

## Активы — `/api/assets`

| Метод | Путь | Доступ | Что делает |
|---|---|---|---|
| GET | `/` | login | Список с фильтрами (`?org=&filial=&status=&category=&search=&page=&limit=` и др.) |
| GET | `/search?q=` | login | Полнотекстовый поиск (мин. 2 символа) |
| GET | `/:id` | login | Один актив |
| POST | `/` | auth | Создать. Тело — `createAssetSchema`. `meta` валидируется по схеме типа, если задана (см. `SCHEMA.md`) |
| PUT | `/:id` | auth | Частичное обновление (патч, не полная замена) |
| DELETE | `/:id` | auth | Списание (soft, `status='списан'`, не физическое удаление) |
| POST | `/:id/move` | auth | Перемещение (ответственный/орг/филиал/локация) с записью в `history` |
| POST | `/bulk-move` | auth | Массовое перемещение по списку id, атомарно в транзакции, `ids_assigned`/`ids_failed` в ответе |
| POST | `/bulk-assign-inv` | auth | Массовое присвоение инв. номеров по правилу организации, та же атомарность |
| GET/POST/DELETE | `/:id/photos(/:photoId)` | login/auth/auth | Фотографии актива |

## Схема типизированных meta-полей — `/api` (types.routes.js)

Добавлено в PROD-1..4, см. `SCHEMA.md` для формата.

| Метод | Путь | Доступ | Что делает |
|---|---|---|---|
| GET | `/meta-keys` | login | Канонический список ключей (`META_KEYS`) — единственный источник, фронт не дублирует |
| GET | `/field-schemas` | login | Вся карта `type_code → поля` разом |
| PUT | `/field-schemas/:type_code` | auth | Сохранить схему для типа. Тело `{ fields: [...] }`, Zod-валидация |
| DELETE | `/field-schemas/:type_code` | auth | Сбросить на дефолт (категорийный fallback) — НЕ то же самое, что сохранить пустой массив |
| GET | `/type-codes` | login | Справочник типов устройств (`code`/`name`/`tab`) |
| PUT | `/type-codes` | auth | Полная замена набора типов |
| GET | `/type-mapping` | login | Вспомогательная карта code→name |

## Справочники организаций/структуры

| Ресурс | База | Доступ на запись | Особенности |
|---|---|---|---|
| Организации | `/api/orgs` | admin (ликвидация/переименование) | `POST /:id/rename`, `POST /:id/liquidate` — не DELETE, орг. не удаляются физически |
| Правила инв. номеров | `/api/orgs/:id/inv-rules` | auth | `PATCH`/`PUT`/`DELETE` + `POST .../delete-force` (обход защиты, если правило используется) |
| Филиалы | `/api/filials` | auth | `POST /:id/close` вместо DELETE (см. `row-closed` в UI) |
| Локации | `/api/locations` | auth | Аналогично, `POST /:id/close` |
| Категории | `/api/categories` | auth | `PUT /:tab` — заменяет список категорий для вкладки |
| Сотрудники | `/api/employees` | auth | `POST /:id/reassign-assets` — при увольнении, см. `employees.js` UI |

## Коды ошибок

Большинство ошибок валидации/бизнес-логики — `400` с телом `{ error: "..." }`.
`401` — не залогинен/неверный пароль. `403` — недостаточно прав (например,
`viewer` пытается писать). `404` — ресурс не найден. `500` — необработанная
ошибка сервера.
